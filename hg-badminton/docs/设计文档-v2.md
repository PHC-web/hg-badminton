## 1. 产品概述

小程序提供两大能力：

1. **日常活动报名**：组织日常打球活动，支持限报、排队补位、代报名。
2. **比赛管理**：以团体单循环赛为主（后续可扩展循环+淘汰、单淘汰），覆盖队伍报名、对阵、记分、实时赛果与观众审批。

## 3. 账号与注册

1. 微信一键登录（`uni.login` → 云对象 `wxLogin` 换取 openid）。
2. 首次需完善：**手机号（必填）**、真实姓名、部门（可选）。
3. 手机号用于关联活动报名人员、比赛队员，以及后续代报名常用联系人。
4. 默认 `roles: ['member']`；不提供演示身份切换。
5. 超级管理员：云数据库手动设置 `roles` 含 `super_admin`，再用其他微信号登录由超管/管理员指定角色。

## 4. 日常活动报名

### 4.1 发布活动（超管/管理员）

可配置：

- 活动名称、活动时间、活动地点
- 限制报名人数（正选名额）
- 报名开始时间、报名结束时间
- 可报名组别（如 A队 / B队，由管理员维护；未选则全体可见）
- 报名须知

状态：`draft` → `open` → `closed` → `finished`

> **组别 ≠ 角色**。组别是组织单元（A队、B队等）；角色是权限身份（管理员、队长等）。活动按组别控制可见性：非允许组别的用户在列表中看不到该活动。

### 4.2 报名

- 仅活动「可报名组别」内的用户可见并可报名（管理员始终可见）。
- 填写：真实姓名、部门；首次填写后写入用户档案，下次自动带出。
- **代报名**：可为他人报名，被代报人信息可存为「常用报名人员」。
- 未满员：进入正式名单 `confirmed`。
- 已满员：进入候补队列 `queued`，按报名时间排序。

### 4.3 排队补位

有人取消正式报名后：

1. 按队列顺序将第一位候补升为正式。
2. 发送微信订阅消息/模板消息提醒（本地演示用 toast/记录通知日志；云端接订阅消息）。

### 4.4 取消报名

报名结束时间前可取消；若取消者为正式名额，触发补位。

### 4.5 名单查看

可见该活动的用户均可查看正式名单与候补队列。活动详情不展示「可报组别」配置项。

## 5. 比赛（本期：单循环赛）

后续扩展：循环赛+淘汰赛、单淘汰赛。本期仅实现 **单循环积分赛**。

### 5.1 发布比赛（超管/管理员）

- 名称、比赛时间、地点
- 赛制：固定 `round_robin`（UI 可展示另两种为「即将开放」）
- 限定报名队伍数
- 每支队伍限定男/女人数
- 报名开始/结束时间、报名须知
- 记分规则（默认 21 分制三局两胜）

### 5.2 队长队伍报名

队长创建队伍：

- 队名（必填）、部门（必填）、队伍宣言（选填）
- 可直接录入成员：姓名、手机号、性别、身份证号、岗位
- 校验男女人数上限与总名额

状态：`draft` → `submitted`（报名截止后锁定）

### 5.3 队员自行报名

1. 选择已有队伍，填写个人信息。
2. 提交后状态 `pending`，待队长审批。
3. 通过后加入队伍；队伍满员或对应性别已满则不可再加入。
4. **无候补队列**。

### 5.4 取消报名

- 队员申请取消 → 队长审核通过后移除。
- 队长可直接移除某成员。

### 5.5 生成对阵

报名截止后，管理员生成单循环对阵：全部队伍两两交手，自动排场地/轮次。

### 5.6 查看对阵

- **参赛者**（队伍成员/队长/指派裁判/管理员）：直接查看。
- **非参赛者**：申请成为观众 → 超管/管理员审批通过后可查看对阵与赛果。

### 5.7 裁判与记分

- 超管/管理员为每场团体对阵指派裁判。
- 裁判进入记分：局分加减、净胜 2、30 分封顶、三局两胜。
- 实时同步赛果给参赛者、裁判、已批准观众。

### 5.8 实时赛果

展示积分榜（胜 2 / 负 1）、最新完赛比分。

## 6. 导航结构（TabBar）

| Tab | 说明 |
| --- | --- |
| 日常活动 | 日常活动列表 / 入口 |

## 7. 数据模型

```
user
  _id, openid, phone, realName, department, nickname, avatar
  roles[]  // member | captain | referee | admin | super_admin
  contacts[]  // 常用代报名人员 { name, phone, department }

activity
  name, location, startTime, endTime
  registerStart, registerEnd, maxCount
  allowRoles[]  // 可报名组别
  notice, status, creatorId

activity_registration
  activityId, userId?, name, phone, department
  isProxy, proxyByUserId
  status  // confirmed | queued | cancelled
  queueNo, createdAt

match
  name, location, startDate, endDate
  registerStart, registerEnd
  progression  // round_robin | group_knockout | single_knockout（本期仅 round_robin）
  maxTeams, maxMalePerTeam, maxFemalePerTeam
  notice, scoring, status, creatorId

team
  matchId, name, department, slogan, captainId
  members[]  // { userId?, name, phone, gender, idCard, job, status }
  // member.status: active | pending | cancel_pending

fixture / sub_fixture / score_log  // 同 v1，简化为单循环团体对阵

match_spectator
  matchId, userId, status  // pending | approved | rejected
  reason, reviewerId
```

## 9. 与 v1 差异

- 去掉用户自助「角色申请」；改为管理员指定。
- 新增日常活动模块（限报、排队、代报名）。
- 比赛本期仅单循环；去掉密码门、照片墙（可后续加回）。
- 新增观众审批观看对阵/赛果。
- 队员入队需队长审批；满员/性别满不可再进。
