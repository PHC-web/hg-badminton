# 云函数架构

```
客户端 api
    │
    ▼
hg-gateway（云对象，唯一入口）
    │  invoke({ service, action, data, _userId })
    ├──────────────┬──────────────┐
    ▼              ▼              ▼
 hg-base      hg-activity     hg-match
 基础数据        日常活动         比赛
```

## 职责

| 云函数/对象 | 类型 | 职责 |
| --- | --- | --- |
| `hg-gateway` | 云对象 | 鉴权透传、路由分发、统一错误 |
| `hg-base` | 云函数 | 微信登录、资料、角色、联系人、通知 |
| `hg-activity` | 云函数 | 活动发布、报名、候补、取消 |
| `hg-match` | 云函数 | 比赛、队伍、对阵、记分、赛果、观众 |
| `hg-api` | 云对象 | **已废弃**，仅兼容转发到 gateway |

## 公共模块

| 模块 | 说明 |
| --- | --- |
| `hg-shared` | fail / nid / 用户查询 / createHandler |
| `hg-core` | 计分、循环赛、权限工具 |
| `hg-config` | 读取微信配置（优先环境变量） |

## 调用约定

```js
await uniCloud.importObject('hg-gateway').invoke({
  service: 'base',      // base | activity | match
  action: 'wxLogin',    // 各服务内的动作名
  data: { code },
  _userId: 'u_xxx'      // 登录后带上
})
```

客户端封装见 `src/api/index.js` 的 `CLOUD_ROUTES`。

## 环境变量

在 **`hg-base`**（不是 gateway）上配置：

- `WX_APPID`
- `WX_APP_SECRET`

## 上传顺序建议

1. 公共模块：`hg-shared` → `hg-core` → `hg-config`
2. 业务云函数：`hg-base` → `hg-activity` → `hg-match`
3. 网关云对象：`hg-gateway`
4. 数据库 schema：至少 `users`、`groups`、`activities`、`activity_registrations`、`notifications`
5. （可选）更新或删除旧的 `hg-api`

## 数据模式（客户端）

默认 **全部上云**，业务 API 只走 `hg-gateway`，不再回落本地 storage。

| 开关 | 位置 | 说明 |
| --- | --- | --- |
| `USE_LOCAL_SIM` | `src/utils/constants.js` | 编译期强制本地（`true` 时无法切回云端） |
| 设置页「云端 / 本地」 | 我的 → 设置 | 运行时写入 `hg_data_mode` |

本地模式：全部走 `src/cloud/service.js` + 本地库，可用于离线调试；登录页显示「本地模拟登录」与游客。

## 迁移状态

- **已上云（默认）**：登录、资料、角色、组别、日常活动、比赛全流程
- **本地→云端**：冷启动一次性导入（`hg_local_migrated_v1` / `hg_local_match_migrated_v1`），仅云端模式执行

## 上传注意（比赛上云后）

1. 公共模块：`hg-shared` → **`hg-core`（含排程/兼项）** → `hg-config`
2. 业务：`hg-base` → `hg-activity` → **`hg-match`（完整）**
3. 网关：`hg-gateway`
4. Schema：补传 `matches` / `teams` / `match_items` / `fixtures` / `sub_fixtures` / `score_logs` / **`match_spectators`**
